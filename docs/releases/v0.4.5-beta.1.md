# DevHarness Kit v0.4.5-beta.1 Goal UX Hardening

Status: beta developer preview. This is not a stable 1.0 release.

## Summary

V0.4.5-beta.1 focuses on Goal UX and agent ergonomics. It keeps goal completion strict,
but makes the correct path easier for agents and developers to follow.

## Highlights

- The default agent entry is now goal-first. The old
  `.agents/skills/devharness-java-development` memory-first skill is removed
  from the packaged skill set.
- `scripts/install-agent-adapters.sh` installs Claude Code, OpenCode, and Comate
  adapters, supports `--dry-run`, `--force`, `--mode copy|link`, `--jar`, and
  legacy cleanup.
- `dhk configure init/show/doctor/explain` manages
  `.agents/devharness/config.json` using the flat
  `devharness-config/v1-alpha` dotted-key schema.
- `verification.compile.mode` and `verification.test.mode` can be `auto`,
  `manual`, or `disabled`.
- Manual compile/test modes become `manual-compile` and `manual-test` checks.
  They require project-local manual evidence and block `goal complete` when
  evidence is missing.
- Disabled compile/test modes are replaced by the `verification-risk` check,
  which requires waiver reason, approver, risk scope, and rollback evidence.
- `dhk goal next --json` exposes a machine-readable evidence contract with
  required evidence, structured fields, allowed/forbidden actions, blockers, and
  the next command.
- `dhk goal step --template` prints the current action's required evidence
  fields without writing to SQLite.
- `dhk goal step --field key=value` supports repeated structured evidence
  fields while preserving existing `--evidence` behavior.
- `dhk goal step --dry-run` validates evidence and policy without inserting a
  `goal_step` row.
- `dhk goal audit` provides read-only completed-goal review.
- `dhk goal recheck` reruns checks without reopening a completed goal.
- `dhk goal verify --level fast|standard|release` separates preflight,
  completion readiness, and release review.
- The `devharness-goal-development` skill now recommends template/field/dry-run
  usage and treats `fast` verify as a preflight only.
- Graph-aware adapters remain opt-in: use them only when `GOAL_CONTEXT.md`
  reports `graph_required=true` or the selected profile is graph-aware. Strict
  skills must not self-apply `graph impact --allow-stale`.

## Verification

Before publishing this release, run:

```bash
mvn -q test
mvn -q -DskipTests package
git diff --check
```

Smoke-test the new UX commands:

```bash
dhk goal next --goal <goal-key> --json
dhk goal step --goal <goal-key> --template
dhk goal step --goal <goal-key> --summary "Dry run" --field evidence=ok --dry-run
dhk goal verify --goal <goal-key> --level fast
dhk goal verify --goal <goal-key> --level standard
dhk goal verify --goal <goal-key> --level release
dhk goal audit --goal <goal-key>
dhk goal recheck --goal <goal-key>
```

Smoke-test adapter and configuration behavior:

```bash
scripts/install-agent-adapters.sh --project-root <tmp-project> --target all --dry-run
dhk configure init --project-root <tmp-project> --preset springboot-manual-ide-test --force
dhk configure show --project-root <tmp-project> --json
dhk configure doctor --project-root <tmp-project> --json
mvn -q -Dtest=GoalSkillPackagingTest test
mvn -q -Dtest=ConfigureCommandIntegrationTest test
```

## Known Limits

- `fast` verify is a preflight. It is not a completion proof.
- `release` verify reports artifact passport status, but the passport is
  normally generated by `goal complete`.
- JSON output remains an alpha contract before 1.0; consumers should tolerate
  additional fields.
- The config schema is flat string JSON in this release; nested JSON objects are
  documented as a future direction, not the current parser contract.
- Manual evidence records what a human, IDE, or CI environment verified. It does
  not replace code review or production release controls.
