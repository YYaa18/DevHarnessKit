# DevHarness Kit v0.4.6-beta.1 ECC Control Panel

Status: beta developer preview. This is not a stable 1.0 release.

## Summary

V0.4.6-beta.1 absorbs the useful parts of ECC without adopting ECC's heavier
multi-agent platform shape. The release keeps DevHarnessKit local-first and
goal-first, then adds a governed local control panel for configuration, adapter
installation, status, doctor, repair, and uninstall.

## Highlights

- Added `scripts/devharness-control-panel.sh` as the recommended setup and
  readiness entrypoint.
- The control panel supports `configure`, `plan`, `install`, `status`, `doctor`,
  `repair`, and `uninstall`.
- `.agents/skills` remains the source of truth. Claude Code, OpenCode, and
  Comate files are generated adapters.
- `configure` writes:
  - `.agents/devharness/config.json`
  - `.agents/devharness/policy.json`
  - `.agents/devharness/agent-manifest.json`
  - `.agents/devharness/install-state.json`
  - `.agents/graph/config.json`
- `plan` is read-only and shows writes, copies/links, removals, chmod, optional
  jar install, and warnings.
- `status` supports `text`, `json`, and `markdown`.
- `doctor` reports missing source/config/manifest/install-state/adapter files
  and prints a repair command.
- `scripts/install-agent-adapters.sh` is deprecated as a direct user entry and
  remains available as a compatibility wrapper around
  `devharness-control-panel.sh install`.
- Release metadata checks require Maven `project.version`, README,
  `CHANGELOG.md`, and `docs/releases/v0.4.6-beta.1.md` to stay synchronized.
- Release coverage checks require generated JaCoCo line coverage to stay at or
  above 60% before beta artifacts are published.
- Version metadata checks now also require README, compatibility docs, migration
  docs, and `dhk version` to agree on schema v15.
- CI packages with the release archive profile so jar, zip, and tarball checks
  exercise the same artifact set expected by release review.
- `docs/INDEX.md` is the documentation map for onboarding, reference docs,
  experimental surfaces, release operations, and historical plans.
- Downloadable release archives are intentionally lean and user-facing: they
  include the runtime jar, installers, adapter assets, README/license/security
  notices, changelog, and runtime control-panel scripts, but omit repository
  docs, release-process docs, CI gates, smoke scripts, and local development
  helper scripts.
- Windows Java 17 CI hardening fixes UTF-8 CLI output capture, Maven
  `mvn.cmd`/`mvnw.cmd` process resolution, platform-specific `.sh`/`.cmd` test
  substitutes, and `/`-normalized displayed source paths.

## Boundaries

- No daemon.
- No dashboard or operator service.
- No Graph parser expansion in this release.
- No write-capable multi-agent orchestration. External model consultation, when
  added later, should remain advisory-only.
- Config output uses the existing flat `devharness-config/v1-alpha` dotted-key
  schema. Nested config JSON from the planning notes is not the runtime
  contract.

## Verification

Run:

```bash
git diff --check
mvn -q -Dtest=GoalSkillPackagingTest test
mvn -q -Dtest=ConfigureCommandIntegrationTest test
mvn -q -DskipTests package
scripts/check-version-metadata.sh 0.4.6-beta.1
scripts/check-coverage-threshold.sh 60
scripts/release-gate.sh --skip-package
```

Control panel smoke:

```bash
CP_ROOT="$(mktemp -d)"
mkdir -p "$CP_ROOT/.agents/skills"
cp -R .agents/skills/devharness-goal-development "$CP_ROOT/.agents/skills/"
cp -R .agents/skills/devharness-graph-aware-development "$CP_ROOT/.agents/skills/"

scripts/devharness-control-panel.sh plan --project-root "$CP_ROOT" --target all --dry-run
scripts/devharness-control-panel.sh configure --project-root "$CP_ROOT" --target all --preset springboot-manual-ide-test --compile-mode manual --test-mode manual --graph required --force
scripts/devharness-control-panel.sh status --project-root "$CP_ROOT" --status-format json
scripts/devharness-control-panel.sh status --project-root "$CP_ROOT" --status-format markdown
scripts/devharness-control-panel.sh doctor --project-root "$CP_ROOT" --target all
scripts/devharness-control-panel.sh uninstall --project-root "$CP_ROOT" --target all --dry-run
```
