# DevHarness Kit v1.0.0 Stable Release

Status: stable. This is the first non-prerelease DevHarness Kit release.

## Summary

`v1.0.0` promotes the narrow DevHarness Kit core to a stable contract while
keeping experimental surfaces bundled for dogfooding and adapter compatibility.
The release remains local-first: no daemon, no cloud sync, and no LLM API calls.

## Stable Surface

The 1.0 stable contract covers:

- `dhk help` and `dhk version`
- `dhk doctor`
- `dhk configure init/show/doctor/explain`
- `dhk status` and `dhk readiness`
- `dhk advise` and `dhk quickstart`
- memory core: `init`, `add`, `confirm`, `search`, `export`, `checkpoint`,
  `recover`, and `backup`
- goal core: `start`, `resume`, `next`, `step`, `status`, `export`, `verify`,
  `complete`, `audit`, and `recheck`
- BDD acceptance harness: scenario creation, lint, evidence import, verify,
  coverage, and traceability bindings for spec, goal, workflow, graph input,
  and tests
- Graph Lite stable-advisory output: `status`, `index`, `impact`, and `export`
  command shape, freshness metadata, and generated export anchors
- documented generated-export anchors for current context, goal context,
  goal summary, work brief, artifact passport, and BDD context/evidence/coverage
  reports
- release packaging, checksums, license/security/changelog notices, and
  installer entrypoints
- stable-candidate installer/control-panel script entrypoints: `install.sh`,
  `scripts/install-agent-adapters.sh`, and `scripts/devharness-control-panel.sh`
  commands `configure`, `plan`, `install`, `status`, `doctor`, `repair`, and
  `uninstall`

See `docs/STABLE_CONTRACT.md` and `docs/STABLE_CANDIDATE.md` for the exact
contract.

## Still Outside The Stable Contract

- DB inspection remains beta. Use appropriate local credentials; SQL guardrails
  and JDBC read-only hints are not a database permission boundary.
  The MySQL 5.1/8 compatibility matrix is documented, but fixture/unit coverage
  is not live server evidence and does not promote DB inspection to stable.
- Graph Lite is stable-advisory, not a correctness proof. Graph-aware Goal
  orchestration beyond the documented Graph output contract remains
  experimental advisory context.
- Skill governance has a stable-candidate `contract.json` and local report
  schema, but full governance enforcement, direct `.agents/skills/` layout
  details, and `skill_contract` SQLite rows remain experimental or internal.
- Policy hooks have a stable-candidate local `devharness-policy/v1` schema and
  documented hook behavior, but they are not a sandbox, permission boundary, or
  stable public automation API.
- Routine reporting has stable-candidate local report schemas
  `goal-metrics/v1`, `goal-replay/v1`, and `routine-summary/v1`, plus CI-safe
  aggregate export helper files. The public routine CLI packaging, dashboards,
  schedulers, and direct SQLite table details remain experimental or internal.
- ECC Control Panel user-facing package script entrypoints are
  stable-candidate, but generated `.agents/`, `.claude/`, and `.comate/`
  adapter layouts, rule contents, alpha install-state/manifest files, and
  private helper structure remain experimental or internal.
- `AGENT_BRIEF.json` remains alpha adapter protocol.

## Packaging Notes

Release artifacts are built from Maven `project.version`:

```text
dhk-cli-1.0.0-all.jar
devharnesskit-1.0.0.zip
devharnesskit-1.0.0.tar.gz
SHA256SUMS
ARTIFACT_MANIFEST.json
```

The downloadable archives intentionally include only user-facing runtime
content: `lib/dhk.jar`, `install.sh`, README files, license/security/changelog
notices, agent skills, knowledge packs, Comate rules, and runtime setup scripts.
Repository docs, CI gates, release-process scripts, and development helper files
are not bundled.

## Notable Changes Since v0.4.6-beta.1

- README, security policy, release checklist, compatibility docs, and metadata
  checks now distinguish stable releases from prerelease beta wording.
- Release gates accept stable status markers for non-prerelease versions while
  retaining prerelease warning checks for versions with a hyphen suffix.
- The installer wizard has a clearer interactive flow and no longer looks for a
  fixed `0.4.6-beta.1` jar fallback.
- The 1.0 release keeps one shaded CLI jar and one release archive for install
  simplicity.
- The BDD acceptance harness is promoted into the stable contract after the
  L0-L9 acceptance plan passed. BDD scenarios remain acceptance intent, not
  implementation proof without accepted evidence and goal checks.
- The default release gate now runs the curated Graph Lite precision suite and
  writes structured diagnostics under `target/graph-lite-precision/result.json`.
- Skill Contract docs now name the stable-candidate `skill-contract/v1` schema
  and keep trust/score output framed as local governance signals rather than
  sandboxing or correctness proof.
- The default release gate now checks built-in skill lint/verify/audit output;
  audit must have zero critical and zero high findings, while wrapper-script
  review remains explicit.
- DB compatibility docs now separate MySQL 5.1 production-floor, MySQL 8 local,
  Connector/J 5.1, fixture/unit, and optional live-smoke evidence so release
  notes do not overstate DB stability.

## Verification

Recommended release verification:

```bash
git diff --check
scripts/check-version-metadata.sh 1.0.0
mvn -B clean package -P release-archive
scripts/release-gate.sh --skip-package
java -jar target/dhk-cli-1.0.0-all.jar version
```

`scripts/release-gate.sh --skip-graph-lite-precision` is reserved for targeted
diagnosis after the precision suite has already been run and recorded.

GitHub release assets should include the jar, zip, tarball, SHA256 checksum
file, and `ARTIFACT_MANIFEST.json` generated from the final tagged commit.
